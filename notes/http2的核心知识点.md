# HTTP/2 核心知识点

HTTP/2 的核心知识点可以归纳为**一个基础架构 + 四大核心机制**，以及它与 HTTP/1.x 的关键差异。以下是系统性的梳理。

## 一、基础架构：二进制分帧层（Binary Framing）

这是 HTTP/2 最根本的改变。

- **HTTP/1.x**：纯文本协议，请求和响应以换行符分隔的明文传输。
- **HTTP/2**：在应用层和传输层之间增加了**二进制分帧层**。所有通信（请求、响应、头部、主体）都被拆分成更小的、**二进制格式的帧（Frame）**。

**核心概念：**

- **帧（Frame）**：最小通信单位（如 HEADERS 帧、DATA 帧、SETTINGS 帧），带有类型、长度、标志位和流标识符。
- **消息（Message）**：完整的请求或响应，由一组帧组成。
- **流（Stream）**：连接中的双向字节流，一个请求/响应对应一个流，用唯一的 **Stream ID** 标识。

> 二进制协议虽然损失了人类可读性，但极大提升了解析效率和精确度，是多路复用的物理基础。

## 二、四大核心机制

### 1. 多路复用（Multiplexing）

HTTP/2 最重要的性能提升来源。

- **原理**：在一个 **TCP 连接**上，可以同时存在多个流（Stream）。不同请求的帧可以**交错发送**（Interleaving），接收端根据 Stream ID 重新组装。
- **解决的问题**：
  - HTTP/1.1 的**应用层队头阻塞**（Head-of-Line Blocking）：一个连接上只能串行处理请求，前一个响应慢会阻塞后一个。
  - **浏览器连接数限制**（通常 6-8 个/域名），不再需要“域名分片”等优化手段。

### 2. 头部压缩（HPACK）

针对 HTTP/1.1 头部冗余的优化。

- **问题**：现代网页请求众多，每次都要携带大量重复的头部字段（如 User-Agent、Accept、Cookie），浪费带宽。
- **HPACK 算法**：
  - **静态表**：预定义 61 个常用头部字段。
  - **动态表**：连接级别的缓存，两端共同维护，遇到重复的头部只传索引号。
  - **霍夫曼编码（Huffman Coding）**：对字符串值进行压缩。
- **效果**：显著减少头部体积，且能防止 CRIME/BREACH 等压缩侧信道攻击。

### 3. 服务器推送（Server Push）

允许服务器**主动**向客户端发送资源。

- **场景**：客户端请求 `index.html`，服务器预判接下来会需要 `style.css` 和 `app.js`，于是主动将这些资源通过 PUSH_PROMISE 帧推送给客户端，省去客户端解析 HTML 后再发起请求的时间。
- **注意事项**：推送必须基于客户端明确的请求，且客户端有权拒绝（RST_STREAM）。实际应用中若使用不当（如推送缓存已存在的资源），反而浪费带宽。

### 4. 流优先级与依赖（Stream Priorities）

让客户端可以表达请求的“重要性”。

- 客户端可以为一个流分配**权重（Weight）**，并声明它**依赖于（Dependency）**另一个流。
- 服务器（或中间代理）根据这些信息决定资源分配和帧的发送顺序，优先处理关键资源（如首屏 CSS），提升用户体验。

## 三、其他关键特性

| 特性 | 说明 |
| --- | --- |
| **流量控制（Flow Control）** | 基于流的逐跳（hop-by-hop）控制，使用 WINDOW_UPDATE 帧，类似于 TCP 滑动窗口，但作用于 HTTP/2 的流级别。 |
| **单 TCP 连接** | 理论上所有请求复用一个连接，减少了 TCP/TLS 握手开销和慢启动惩罚。 |
| **状态语义兼容** | 方法（GET/POST）、状态码（200/404）、头部字段等核心语义与 HTTP/1.1 保持一致，保证平滑升级。 |
| **伪头部（Pseudo-Headers）** | 请求使用 `:method`、`:scheme`、`:authority`、`:path`；响应使用 `:status`，替代了 HTTP/1.1 的请求行/状态行。 |

## 四、HTTP/2 的局限性（必须了解的边界）

1. **TCP 层队头阻塞仍在**：虽然解决了应用层队头阻塞，但如果一个 TCP 包丢失，后续所有流的帧都必须等待重传（TCP 保证有序性）。这正是 **HTTP/3（QUIC）** 使用 UDP 想要彻底解决的问题。
2. **加密并非协议强制，但 facto 强制**：RFC 7540 允许明文 HTTP/2（h2c），但所有主流浏览器（Chrome、Firefox、Safari）**只支持基于 TLS 的 HTTP/2（h2）**，且通常要求 TLS 1.2+ 和特定加密套件。
3. **服务器推送收益有限**：在实践中，缓存策略复杂，推送常被禁用或替代为 HTTP/2 预加载提示（`<link rel="preload">`）。

## 五、核心知识总结图

```text
HTTP/2 核心 = 1 个基础 + 4 大机制
├── 基础：二进制分帧（Frame/Stream）
├── 机制 1：多路复用（Multiplexing）—— 解决应用层队头阻塞
├── 机制 2：头部压缩（HPACK）—— 减少冗余
├── 机制 3：服务器推送（Server Push）—— 降低 RTT
└── 机制 4：流优先级（Priority）—— 优化资源调度
```
































































理解 HTTP/2 的关键在于：**它并没有改变 HTTP 的语义，而是彻底改变了 HTTP 的传输方式**。
