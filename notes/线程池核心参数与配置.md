# 线程池核心参数与配置

## 七大参数（必须默写）

1. corePoolSize：核心线程数，常驻存活（除非 allowCoreThreadTimeOut）
2. maximumPoolSize：最大线程数，任务队列满后才扩容到这里的线程
3. keepAliveTime：非核心线程闲置多久回收
4. unit：keepAliveTime 的时间单位
5. workQueue：任务队列，核心线程满后新任务进队列
6. threadFactory：线程工厂，统一命名（排查线程_dump 时救命）
7. rejectedExecutionHandler：队列满且线程到上限时的拒绝策略

## 执行流程（面试必考）

提交任务 → 核心线程有空？→ 有则执行
→ 没有 → 队列没满？→ 入队等待
→ 队列满 → 线程数 &lt; max？→ 创建非核心线程执行s
→ 到 max 且队列满 → 触发拒绝策略

## 四种拒绝策略

- AbortPolicy（默认）：抛 RejectedExecutionException
- CallerRunsPolicy：让提交任务的线程自己跑，起到反压作用
- DiscardPolicy：静默丢弃，最危险
- DiscardOldestPolicy：丢弃队列最老任务再重试提交

## 线程数怎么配（没有银弹，只有估算）

- CPU 密集型：N_cpu + 1
- IO 密集型：N_cpu × (1 + 等待时间/计算时间)，实际靠压测校准
- 公式只是起点，最终用压测 + 监控（活跃线程数、队列长度）调整

## 为什么不用 Executors 工厂方法

- newFixedThreadPool / newSingleThreadExecutor：队列是
  LinkedBlockingQueue 无界，任务堆积会 OOM
- newCachedThreadPool：maximumPoolSize 为 Integer.MAX_VALUE，
  瞬时高并发会创建海量线程
- 结论：生产环境用 ThreadPoolExecutor 显式构造，参数心里有数
