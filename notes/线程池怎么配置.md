# 线程池怎么配置

## 一、线程数（Pool Size）配置

线程数的配置取决于任务类型，这是最核心的参数。

- **CPU 密集型任务**（复杂计算、数据处理）：  
  推荐 `corePoolSize = CPU 核心数 + 1`。多出的 1 个线程用于填补 GC 或页缺失带来的微小空闲，最大化 CPU 利用率。[1]

- **IO 密集型任务**（网络请求、数据库、文件读写）：  
  推荐 `corePoolSize = 2 × CPU 核心数`，或更精确地使用公式 `NCPU / (1 - 阻塞系数)`（阻塞系数通常在 0.5~0.9 之间）。[2]

- **混合型任务**：  
  建议拆分为独立的线程池，或采用 `ForkJoinPool` 分别处理计算与 IO，避免相互阻塞。[3]

- **maximumPoolSize**：  
  通常设置为 `corePoolSize` 的 1.5~2 倍，或根据系统内存、句柄数等资源上限设定，作为突发流量的缓冲。[4]

## 二、任务队列（Work Queue）选择

队列的类型和容量直接决定了系统的稳定性：

| 队列类型 | 特性 | 适用场景 |
|---|---|---|
| `LinkedBlockingQueue` | 可指定容量，链表结构 | 最常用，**生产环境务必指定有界容量** |
| `ArrayBlockingQueue` | 有界，基于数组，可选公平锁 | 需要严格控制队列长度、关注吞吐量的场景 |
| `SynchronousQueue` | 不存储元素，直接移交线程 | 高并发短任务，如快速响应的 RPC 场景 |
| `PriorityBlockingQueue` | 支持按优先级排序 | 任务有明显优先级的业务 |

**核心原则**：生产环境**禁止使用无界队列**（如默认的 `LinkedBlockingQueue`），否则会在任务堆积时导致 OOM。[5]

## 三、拒绝策略（Rejection Policy）

当线程数达到 `maximumPoolSize` 且队列已满时触发：

- **`AbcondortPolicy`**（默认）：直接抛出 `RejectedExecutionException`，调用方需显式处理异常。[6]
- **`CallerRunsPolicy`**：由**提交任务的线程**（调用者）自己执行该任务。这相当于一种自然的背压（Backpressure）机制，降低上游提交速度，**高可用系统推荐**。[7]
- **`DiscardPolicy`**：静默丢弃任务，**生产环境慎用**，极易导致数据丢失且无感知。[8]
- **`DiscardOldestPolicy`**：丢弃队列中最老的任务，尝试提交新任务。[9]

---

## 四、线程回收与存活时间

- `keepAliveTime`：非核心线程的空闲存活时间，建议设为秒级到分钟级（例如 60 秒），避免线程频繁创建销毁。[10]
- `allowCoreThreadTimeOut(true)`：允许核心线程在空闲时也被回收。适合流量具有明显波峰波谷、希望彻底释放资源的场景。[11]

---

## 五、线程工厂（ThreadFactory）

**强烈建议自定义 `ThreadFactory`**，用于：

- **线程命名**：按 `业务名-pool-序号` 格式命名，方便日志排查与监控告警。[12]
- **守护线程标识**：根据业务性质设置 `daemon` 状态，防止阻塞 JVM 退出。
- **异常捕获**：通过 `UncaughtExceptionHandler` 统一处理运行时异常，避免任务异常被吞没导致问题无法定位。[13]

---

## 六、动态配置与监控

- ThreadPoolExecutor 支持运行时通过 `setCorePoolSize()` 和 `setMaximumPoolSize()` 动态调整参数，建议对接配置中心（如 Apollo、Nacos）实现热更新。[14]
- 关键监控指标：活跃线程数（`activeCount`）、队列积压长度（`queue.size()`）、完成任务数（`completedTaskCount`）、拒绝任务数（自定义统计）。[15]

---

## 七、生产环境配置 Checklist

- [ ] 队列是否指定了**有界容量**？
- [ ] 线程是否通过自定义 `ThreadFactory` **命了名**？
- [ ] 拒绝策略是否选择了**可感知、可告警**的策略（如 `CallerRunsPolicy`）？
- [ ] 线程数是否结合了 CPU 核数与任务阻塞特性计算？
- [ ] 是否捕获了任务异常并记录日志？
- [ ] 是否预留了动态调整参数的能力？
